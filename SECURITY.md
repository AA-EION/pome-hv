# Security

The GUI is unelevated. The helper exposes an allowlist of creation, inspection, lifecycle, stopped-VM configuration, checkpoint, EFI boot-order repair, disk-growth and export operations, plus EnableHyperV. It validates requests again, accepts bounded JSON over a current-user named pipe, and verifies the UI PID. The UI checks the elevated helper PID. User input is data, never interpolated PowerShell code. Host security settings, firmware, GPUs and Microsoft binaries are not modified.

Every VM mutation requires pome ownership and an allowed current VM state; the embedded PowerShell program rechecks state before executing. External VMs may be inspected but remain read-only. Settings changes attempt independent CPU/memory/network/name rollback on failure. Checkpoint restore/delete identifies a checkpoint only within the selected VM. Disk growth requires the original operation GUID, original local `macOS.vhdx` path and SCSI slot, no checkpoints, a detached self-contained disk, a larger capacity and a free-space reserve. It does not resize guest partitions. EFI-first repair changes boot ordering without changing Secure Boot. Export uses a new validated operation folder, preserves partial files and writes recovery markers.

All reviewed creation requests consent to guest Secure Boot being disabled. Automatic EFI uses an upstream template with `csr-active-config=03000000`, relaxing guest kext signing and filesystem protection. NullMoth would require additional guest changes, but pome does not apply them. Host Secure Boot and guest Secure Boot are distinct.

Downloads use HTTPS with a small redirect-host allowlist, pinned size and SHA-256, bounded writes, partial-file resume and atomic promotion. Rejected files are quarantined. Archives reject traversal, symlinks, duplicate destinations and excessive expansion. The upstream boot utility is executed unelevated only after authenticating its entire archive. No moving-branch bootstrap script is executed.

Activity's host diagnostic report exports a fixed allowlist of capability and operation-state fields, excluding raw hardware IDs, serials, paths, VM names and journal messages. The separate VM boot-log export is explicit and local: it includes OpenCore logs, panic logs and configuration, which can contain VM identifiers. It requires an off, owned VM without checkpoints, verifies the exact EFI path/journal/SCSI slot, mounts only that EFI disk read-only, bounds file count/size and always dismounts. Review those files before sharing. Local operation markers and `identity.json` also contain private VM information.

Automatic recovery restoration runs in managed code with bounded UDIF/XML/chunk parsing, supported raw/zlib codecs, complete nonoverlapping sector checks, GPT CRC verification and cancellation before publishing a new fixed VHD. The source is first copied with its reviewed digest verified. Outputs cannot overwrite an existing disk; failed partials remain available for inspection. Hyper-V converts that intermediate into a new recovery VHDX before VM registration. No host physical disk is written by the decoder. DMG loading is disabled for automatically configured media, and file boot/panic logging is enabled; guest Secure Boot/SIP choices remain those explicitly reviewed by the user.

**Preview limitations:** the helper is not signed, publisher pinning is absent, path checks are not yet resistant to every malicious concurrent directory/reparse-point swap, and metadata recovery is not an unattended service. Install under protected Program Files before general distribution. Do not expose a development checkout helper as a persistent privileged service. A user-controlled Python path is permitted only in the unelevated UI and is never accepted as an elevated command.

Report security findings privately to the repository maintainers when a reporting channel is configured; do not publish identifiers or sensitive logs. No external reporting or telemetry is implemented by pome.
