# User guide

Creation uses four steps: General, Resources, Installation and Review. Continue checks the name, folder and resource values before advancing; navigation does not submit a VM operation. Review contains explicit license, guest-security and optional start choices. The selected-VM workspace separates Overview, Hardware, Storage, Recovery, Install macOS and Diagnostics tasks.

1. Open pome and choose **This computer** in the compact navigation rail. Unknown values mean insufficient evidence. Use **Inspect with administrator access** if normal discovery cannot list VMs or networks.
2. If Hyper-V is unavailable, read the assessment. **Enable Hyper-V** shows a review before UAC and never reboots automatically. Non-admin discovery may also be unavailable because the account lacks Hyper-V permissions.
3. Choose **Create a Mac** and pick a **macOS version** (OS X 10.7 Lion through macOS 26 Tahoe). Each entry shows its evidence: Sequoia reached Recovery and the installer on the reference host; most others follow upstream OSX-Hyper-V support and are untested by pome; Tahoe and Lion are experimental. The guidance below the picker says whether your processor runs natively or is presented as a model that version recognizes, and blocks combinations macOS cannot run (Ventura and later need AVX2; Sandy/Ivy Bridge stop at Monterey). The default name follows the version and avoids registered names when they can be read. The default storage folder is Documents, or `%USERPROFILE%\Virtual Machines` when Documents is synced by OneDrive. Browse for another local folder if needed, then choose CPU, static memory, disk capacity and a switch. Refreshing preserves edited fields; **Use recommended resources** reapplies CPU/RAM advice. Disconnected is explicit. Pome does not create or modify host networks.
4. Automatic preparation supports Intel hosts from Sandy Bridge to Arrow Lake and AMD families 15h–1Ah from macOS 10.13 (pome downloads the commit-pinned AMD_Vanilla kernel patches and writes the VM's processor count into them, so AMD VMs need 2, 4, 8 or 16 processors and keep that count after creation) and uses bundled isolated Python. Apple recovery is downloaded for the chosen version and cached per version. Tahoe also downloads the pinned MacHyperVSupport 1.0.0 release and replaces the EFI's older guest driver. Two virtual processors are recommended while macOS runs on one active CPU; use powers of two. Review the Apple license and guest security choices. Names, paths, resources, CPU profile and networks are checked before downloading. Destination storage reserves full disk capacity plus an estimated 8 GB of boot media; the helper rechecks actual sizes. The system drive also needs space for the recovery cache. Check the version offered inside Apple's installer; server-selected recovery content is not a fixed OS-version promise.
5. Alternatively, turn off automatic media and browse for trusted EFI/recovery VHDX files. Enter their trusted SHA-256 digests. Calculate buttons identify a local file; compare their results with your trusted build record. Changing the media path clears its previous digest. Prepare a unique identity and suitable CPU profile upstream.
6. Review and create. Windows may request administrator inspection before preparation, and requests approval for creation afterward. **Start the VM and open its console after creation** is off by default and appears in the final review. A failed start preserves the created VM; free host RAM and retry from Library.
7. In Library, select the VM and choose **Start & connect**. The installation guide explains Recovery boot, Disk Utility's **Show All Devices**, erasing only the destination as APFS/GUID, and selecting **macOS Installer** through restarts, then **Macintosh HD**. Keep the EFI/OpenCore disk attached. Pome does not detect installation completion.

8. After macOS starts, run `sudo bash /Volumes/POME-BOOT/Scripts/post-install.sh` in Terminal. It installs the Hyper-V shutdown, time-sync and file-copy daemons and the framebuffer driver that adds display resolutions; approve the driver in Privacy & Security and restart.

Search filters machines by name. VM state refreshes automatically while a guest is running or changing state when pome can list VMs without elevation. Start supports off or saved VMs. Pause retains assigned RAM; Resume continues a paused guest. Save state writes memory/device state to disk and releases host resources. Appearance offers persistent Windows/system, light and dark themes.

Choose **Load settings & checkpoints…** to inspect startup memory, network, disks, firmware boot order and standard checkpoints. A stopped, pome-managed VM can be renamed and have its CPU/static-memory/switch settings edited. The helper validates again and attempts to restore original values on failure, reporting any rollback failures. Disk filenames stay unchanged.

**Put EFI disk first…** restores SCSI 0:0 as the first firmware boot device while preserving Secure Boot. **Expand disk…** grows only the original `macOS.vhdx` at SCSI 0:1 in its original pome directory. Export a backup, shut down and remove checkpoints first. Shrinking is unavailable. After growth, expand the APFS partition/container inside macOS Disk Utility; pome does not modify guest partitions.

Checkpoints require a stopped VM. Restoring replaces changes after that recovery point. Deleting removes the recovery point and asks Hyper-V to merge its changes. Checkpoints depend on the original disks. **Export VM backup…** copies a stopped VM's configuration, disks and checkpoints to a new folder in your chosen local destination. Keep the entire export together. Partial output and `operation.json` are preserved on failure. Native restore/import is not implemented; Hyper-V Manager can import Hyper-V exports.

Automatic creation now builds three disks: OpenCore EFI, the macOS destination and a separate Apple recovery disk. Recovery is restored onto disk rather than loaded into guest RAM, avoiding the allocation failure observed at 4 GB. Keep the EFI and recovery disks intact when erasing the destination in Disk Utility. Compatibility mode currently uses one active macOS CPU. Recovery GUI and an active Sequoia installer were observed on the reference VM; installation completion and first normal boot remain unverified.

For a failed boot, shut down the VM and choose **Diagnostics → Export boot logs…**. Select a local folder. The helper reads only the original EFI disk, copies up to 20 recent logs plus its configuration, and dismounts in `finally`. New automatic media enables file logging. Older media may have no logs. Checkpointed VMs are currently unsupported for this operation. Boot exports include VM identifiers and configuration: review them before sharing. The Activity page's host diagnostic report remains separately privacy-filtered.

**Power → Shut down** asks macOS to shut down through Hyper-V integration and needs the guest tools from step 8. Without them (installer, fresh install) pome explains this instead of hanging. **Reset** restarts immediately and **Turn off** powers off immediately; both lose unsaved guest work. **More → Remove VM…** unregisters a stopped VM with no checkpoints and keeps its files by default; deleting files requires typing the VM name and only removes the VM's own `pome-…` folder when every attached disk is inside it. **More → Open VM folder** opens that folder.

**This computer → Join Hyper-V Administrators…** adds your account to the built-in group after one UAC prompt. After you sign out and back in, listing, power actions and the console run without administrator prompts; creation, disk and file tasks still ask. Members can control every VM on the computer.

VMs not marked as created by pome are shown read-only. Import/ownership adoption is not implemented.

NullMoth is an optional separate download under This computer. Review PolyForm Noncommercial 1.0.0. The verified archive is saved under `%LOCALAPPDATA%/pome/downloads`; no installer, guest security change or GPU assignment runs. A download is not evidence of hardware compatibility.
