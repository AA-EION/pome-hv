# pome visual system

Native Windows Operate surface. The user explicitly requested ExHyperV's UI style and layout on 2026-10-27, superseding the earlier wide navigation/library composition. Keep pome's identity and macOS workflow, using WinUI 3 rather than introducing WPF or copying ExHyperV assets.

The reference is ExHyperV at `f51e0667a8499e88e3f93d4beb221dc48e14f9b5`, especially `img/03.png`, `VirtualMachinesPage.xaml` and `VmCreateView.xaml`. The completed UI pass uses a compact 64px navigation rail (208px expanded), a searchable 232px machine list, and a bounded detail workspace. Below 900 logical pixels the library stacks vertically. Overview, Hardware, Storage, Recovery, Install macOS and Diagnostics tabs separate VM tasks. Power actions use a menu rather than a grid of inactive buttons. A real empty/search state replaces VM controls when no machine is selected.

Creation is a four-step General, Resources, Installation and Review wizard with fixed Back/Continue/Prepare controls. Steps share form values and never submit a mutation through navigation alone. Guest license and security choices are explicit on Review; the application no longer checks those boxes through a combined acceptance dialog. Virtual machines, Create a Mac, This computer, Activity, Networks and Settings remain native navigation destinations.

Use Segoe UI Variable and system text styles, neutral theme resources, blue primary actions, Mica window integration, a theme-aware custom title bar, 28px page gutters, 16–24px section spacing and 10–12px surface corners. Windows/system, light and dark themes are available; the preference is local. High-contrast accent resources defer to system colors. Keep numeric configuration explicit, labels accessible, paths wrapping, and search insensitive to case. No decorative charts, fake usage histories or sample VMs. The status footer is a single compact line; cancellation only appears during cancellable work.

The VM header shows real state and management ownership. State-dependent actions disable when inappropriate; the helper independently rechecks ownership and live state. Settings require a stopped VM and a loaded details record. Boot media preparation and hash calculation preserve form values. Guest firmware consent and irreversible checkpoint restoration or disk growth have explicit review text. Unknown capabilities stay unknown. Standard synthetic graphics is the only default; unsupported GPU/USB/PCIe paths do not become working features by copying a layout.

Visual QA uses the actual native app. The first inspection on 2026-10-27 covered Library and Create at normal/maximized sizes and the Appearance page; the resulting fix batch stretches expander contents, aligns the creation form, sizes the initial window to the work area and integrates titlebar theme colors. Hardware mutation and macOS installation require separate integration evidence.
