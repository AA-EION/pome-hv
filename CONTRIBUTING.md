# Contributing

Keep host safety, explicit evidence and a working non-GPU path ahead of experimental acceleration. Include a small description of behavior, tests, limitations and recovery for each change. Use real source references and exact commits for upstream assertions.

Build and run tests before submitting. New hardware support needs a reproducible test record with actual component IDs, firmware, host/guest builds and the precise milestone reached. Never substitute a mock result for device evidence.

Do not copy noncommercial code into the MIT application. Preserve upstream notices in patches and keep downloaded components outside the repository. Contributions to kernel patches must include source, scope, rollback and an SDK build result. No physical-device operations belong in ordinary CI.
